# 02. Адресация и выбор маршрута

Программа работает в двух режимах. Режим задаётся первым аргументом командной строки.
В первом режиме печатаются свойства блока адресов, во втором выбирается запись таблицы
маршрутов по правилу наибольшего совпадения префикса.

Адреса задаются в десятично-точечной записи, четыре октета по основанию десять.
Поддержка IPv6 не требуется.

## Вывод

Построчно, `ключ значение`, разделитель — один пробел. Порядок строк произвольный.
Лишние строки игнорируются, поэтому отладочный вывод допустим, если он не начинается
с перечисленных ключей.

## Режим 1: свойства блока адресов

```
run.sh subnet <адрес>/<префикс>
```

Аргумент — адрес и длина префикса через косую черту, например `192.168.10.37/24`.
Адрес может быть задан не по границе блока; в этом случае он приводится к адресу сети.

| ключ | значение |
|---|---|
| `network` | адрес сети — младшие биты вне префикса обнулены |
| `broadcast` | широковещательный адрес — младшие биты вне префикса установлены; `none`, если его нет |
| `netmask` | маска в десятично-точечной записи |
| `prefix` | длина префикса, число от 0 до 32 |
| `first` | первый адрес узла |
| `last` | последний адрес узла |
| `hosts` | количество адресов, назначаемых узлам |

Пример:

```
$ run.sh subnet 192.168.10.37/24
network 192.168.10.0
broadcast 192.168.10.255
netmask 255.255.255.0
prefix 24
first 192.168.10.1
last 192.168.10.254
hosts 254
```

### Особые случаи

| префикс | поведение |
|---|---|
| `/31` | блок из двух адресов, оба назначаются узлам: `broadcast none`, `hosts 2`, `first` — адрес сети, `last` — следующий за ним (RFC 3021) |
| `/32` | блок из одного адреса: `network`, `first` и `last` совпадают, `broadcast none`, `hosts 1` |
| `/0` | весь диапазон адресов: `netmask 0.0.0.0`, `network 0.0.0.0`, `broadcast 255.255.255.255`, `hosts 4294967294` |

Для всех остальных длин префикса адрес сети и широковещательный адрес узлам не назначаются,
поэтому `hosts` на два меньше размера блока.

## Режим 2: выбор маршрута

```
run.sh route <файл таблицы> <адрес назначения>
```

Файл таблицы маршрутов содержит по одной записи в строке:

```
<сеть>/<префикс> <интерфейс>
```

Пустые строки и строки, начинающиеся с символа `#`, пропускаются. Поля записи разделены
пробельными символами. Путь к файлу передаётся первым аргументом режима и может быть
абсолютным.

Запись подходит адресу назначения, если адрес и сеть записи совпадают в старших битах,
число которых равно длине префикса записи. Из подходящих записей выбирается запись
с наибольшей длиной префикса. Порядок строк в файле на результат не влияет.

| ключ | значение |
|---|---|
| `via` | интерфейс выбранной записи |
| `prefix` | длина префикса выбранной записи |
| `unreachable` | `true`, если подходящей записи нет |

Пример:

```
$ cat routes.txt
# таблица маршрутов
0.0.0.0/0      eth0
10.0.0.0/8     eth1
10.1.0.0/16    eth2
10.1.2.0/24    eth3

$ run.sh route routes.txt 10.1.2.5
via eth3
prefix 24
```

Если подходящей записи нет, печатается `unreachable true`, а программа завершается
с ненулевым кодом возврата. При наличии маршрута код возврата нулевой.

## Что потребуется учесть

1. Маску длины `n` удобно получать как целое из `n` старших единичных битов; при `n` равном
   нулю маска нулевая, и запись подходит любому адресу назначения.
2. Сравнение адреса с записью выполняется по маске записи, а не по маске сети назначения.
3. Запись с префиксом `/0` — маршрут по умолчанию. Он подходит всегда, но имеет наименьшую
   длину префикса, поэтому выбирается только при отсутствии других подходящих записей.
4. Запись с префиксом `/32` задаёт маршрут к одному адресу и при совпадении выигрывает
   у любой другой записи.
5. Количество адресов узлов для коротких префиксов не помещается в 32-разрядное знаковое
   целое: для `/0` оно равно 4294967294.
6. Если аргументы заданы неверно — адрес не разбирается или длина префикса вне диапазона
   от 0 до 32, — программа печатает сообщение в стандартный поток ошибок и завершается
   с ненулевым кодом возврата.

## Спецификации

- [RFC 4632](https://datatracker.ietf.org/doc/html/rfc4632) — бесклассовая адресация и агрегирование маршрутов
- [RFC 3021](https://datatracker.ietf.org/doc/html/rfc3021) — использование префикса /31 на двухточечных каналах
- [RFC 1918](https://datatracker.ietf.org/doc/html/rfc1918) — частные диапазоны адресов
- [RFC 1812](https://datatracker.ietf.org/doc/html/rfc1812) — требования к маршрутизаторам, правило наибольшего совпадения префикса
