# 04. Разбор сообщения HTTP/1.1

Программа получает на стандартный ввод одно сообщение HTTP/1.1 в виде байтов
и печатает на стандартный вывод результат его разбора.

Разбираются запрос и ответ: строка начала, поля заголовка и тело сообщения.

## Ввод

Одно сообщение целиком, как оно передаётся по соединению. Разделителем строк служит
последовательность CRLF (`0x0D 0x0A`). Заголовочная часть отделяется от тела пустой
строкой, то есть двумя последовательностями CRLF подряд.

```
GET /search?q=hello&page=2 HTTP/1.1
Host: example.org
Accept: text/html
```

Тело может содержать любые байты, в том числе совпадающие с разделителем строк.
Опираться на поиск разделителя в теле нельзя: границы тела задаются полем
`Content-Length` либо передачей по частям.

## Вывод

Построчно, `ключ значение`, разделитель — один пробел. Порядок строк произвольный,
кроме полей заголовка: они выводятся в том порядке, в каком встречены в сообщении.
Лишние строки игнорируются, поэтому отладочный вывод допустим, если он не начинается
с перечисленных ключей.

| ключ | значение |
|---|---|
| `type` | `request` для запроса, `response` для ответа |
| `method` | метод запроса, как он записан в сообщении; только для запроса |
| `target` | цель запроса целиком, вместе со строкой запроса; только для запроса |
| `version` | `HTTP/1.1` |
| `status` | код состояния, три десятичные цифры; только для ответа |
| `reason` | поясняющий текст; только для ответа, может быть пустым |
| `header` | имя и значение поля заголовка через пробел, по строке на каждое поле |
| `body.length` | длина тела в байтах |
| `body.text` | тело как текст; выводится, если тело непустое и состоит из печатных символов |

Имя поля заголовка приводится к нижнему регистру. Значение выводится без окружающих
пробелов и знаков табуляции. Внутренние пробелы значения сохраняются.

Печатными считаются байты от `0x20` до `0x7E` включительно. Если хотя бы один байт тела
выходит за этот диапазон, строка `body.text` не выводится, а `body.length` выводится всегда.

Пример вывода для приведённого выше запроса:

```
type request
method GET
target /search?q=hello&page=2
version HTTP/1.1
header host example.org
header accept text/html
body.length 0
```

## Тело сообщения

Границы тела определяются в следующем порядке.

1. Если есть поле `Transfer-Encoding` со значением `chunked`, тело передано по частям
   и собирается из частей. Значение `body.length` — длина собранного тела.
2. Иначе, если есть поле `Content-Length`, тело — ровно столько байт, сколько указано
   в этом поле. Байты после указанной длины игнорируются.
3. Иначе тело считается пустым и выводится `body.length 0`.

Каждая часть при передаче по частям записывается так: строка с длиной части
шестнадцатеричными цифрами, CRLF, байты части, CRLF. Часть нулевой длины завершает тело.
После неё могут следовать поля концевика; они игнорируются и как поля заголовка
не выводятся. За длиной части могут идти расширения, отделённые точкой с запятой;
они также игнорируются.

## Ошибки

При неверном сообщении программа печатает строку `error <причина>` и завершается
с ненулевым кодом возврата. Прочие строки в этом случае не проверяются.

| причина | когда |
|---|---|
| `bad_start_line` | строка начала не завершена CRLF, не разбирается как строка запроса или строка состояния либо содержит версию, отличную от `HTTP/1.1` |
| `bad_header` | заголовочная часть не завершена пустой строкой; строка поля заголовка без двоеточия; имя поля пустое или содержит знаки, недопустимые в имени, в том числе пробел перед двоеточием; значение `Content-Length` не является десятичным числом |
| `incomplete_body` | байт тела меньше, чем указано в `Content-Length` |
| `bad_chunk` | длина части не является шестнадцатеричным числом, байт части меньше объявленной длины, часть не завершена CRLF либо часть нулевой длины отсутствует |

## Поддерживаемое подмножество

Разбирается только HTTP/1.1. Поддержка HTTP/2 и HTTP/3 не требуется: у них двоичный
формат кадров и иное представление полей заголовка. Сообщения HTTP/1.0 и сообщения
с любой другой версией считаются неверными.

Не требуется: перенос значения поля заголовка на следующую строку, разбор поля заголовка
на составные части, распаковка содержимого по полю `Content-Encoding`, обработка
нескольких сообщений подряд в одном потоке ввода.

## Что потребуется учесть

1. Тело читается как байты. Тело может содержать последовательность CRLF и даже две
   подряд, поэтому заголовочная часть отделяется от тела ровно один раз — по первой
   пустой строке.
2. Поле заголовка может встречаться несколько раз. Выводится каждое вхождение,
   порядок сохраняется.
3. Значение поля отделяется от двоеточия произвольным числом пробелов и знаков
   табуляции; они в значение не входят. Значение может содержать двоеточие,
   поэтому имя отделяется по первому двоеточию в строке.
4. Поясняющий текст в строке состояния может быть пустым, при этом строка `reason`
   всё равно выводится.
5. Перевод строки без возврата каретки разделителем не является.
6. Длина части при передаче по частям записана шестнадцатеричными цифрами в любом
   регистре и не совпадает с длиной всего тела.
