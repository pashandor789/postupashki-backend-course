# 03. Запрос к серверу доменных имён

Программа формирует запросы по протоколу DNS, отправляет их по UDP на указанный сервер,
разбирает ответы и печатает результат в текстовом виде. Повторный запрос того же имени
и типа обслуживается из кеша, пока не истекло время жизни записи.

## Запуск

```
run.sh <адрес сервера> <порт>
```

Адрес и порт сервера передаются в аргументах командной строки. Обращение к системному
распознавателю имён и к любым другим серверам не допускается: сообщение запроса
формируется и сообщение ответа разбирается самостоятельно.

## Ввод

Строки стандартного ввода вида `<имя> <тип>`, по одному запросу в строке. Пустые строки
пропускаются. Обработка заканчивается по достижении конца ввода.

```
www.example.com A
example.com MX
www.example.com A
```

Типы, которые требуется поддерживать: `A`, `AAAA`, `CNAME`, `MX`, `TXT`, `NS`.

## Вывод

На каждую строку ввода печатается блок строк.

```
query www.example.com A
status NOERROR
answer CNAME cdn.example.net. 3600
answer A 93.184.216.34 300
end
```

| строка | содержание |
|---|---|
| `query` | имя и тип в том виде, в каком они прочитаны со стандартного ввода |
| `status` | код ответа сервера либо `TIMEOUT`, если ответ не получен |
| `answer` | одна запись раздела ответа: тип, значение, время жизни в секундах |
| `end` | конец блока |

Коды ответа: `NOERROR` (0), `FORMERR` (1), `SERVFAIL` (2), `NXDOMAIN` (3), `REFUSED` (5).
Прочие значения печатаются в виде `RCODE<число>`.

### Значение записи

| тип | значение |
|---|---|
| `A` | адрес в десятично-точечной записи |
| `AAAA` | адрес IPv6 в сокращённой записи: ведущие нули групп опускаются, самая длинная цепочка нулевых групп заменяется на `::` |
| `CNAME`, `NS` | доменное имя с завершающей точкой |
| `MX` | приоритет, пробел, доменное имя с завершающей точкой |
| `TXT` | содержимое записи без кавычек; несколько строк одной записи выводятся подряд без разделителя |

Строки `answer` идут в том же порядке, в каком записи расположены в разделе ответа.
Выводится только раздел ответа: разделы полномочий и дополнительных сведений
не выводятся. Записи, тип которых не входит в перечень выше, пропускаются.
Если подходящих записей нет, строки `answer` отсутствуют, а строки `query`,
`status` и `end` печатаются как обычно.

## Кеширование

Ответ с кодом `NOERROR`, содержащий хотя бы одну запись, сохраняется в памяти программы.
Срок хранения равен наименьшему времени жизни среди записей раздела ответа. Пока срок
не истёк, повторный запрос того же имени и того же типа обслуживается из кеша: сообщение
по сети не отправляется, а печатаются те же строки `answer` с исходными значениями
времени жизни.

Не сохраняются: ответы с кодом, отличным от `NOERROR`, ответы без записей и ответы,
в которых время жизни равно нулю. Записи разных типов для одного имени хранятся
раздельно. Имя сравнивается без учёта регистра букв.

## Отсутствие ответа

Ответ ожидается не дольше пяти секунд. Если за это время ответ не получен, печатаются
строки `status TIMEOUT` и `end`, после чего программа завершается с ненулевым кодом.
При полученном ответе, в том числе с кодом ошибки, программа продолжает обработку
и завершается с кодом 0.

## Что потребуется учесть

1. Заголовок сообщения занимает 12 байт: идентификатор, поле флагов и четыре счётчика
   разделов. В запросе раздел вопросов содержит ровно один вопрос, установлен бит
   рекурсии, класс вопроса — `IN` (1).
2. Числовые коды типов: `A` — 1, `NS` — 2, `CNAME` — 5, `MX` — 15, `TXT` — 16, `AAAA` — 28.
3. Доменное имя записано последовательностью меток: длина метки, затем её байты; конец
   имени — нулевой байт.
4. Имя может быть задано сжатым: два байта, старшие два бита которых равны единице,
   содержат смещение от начала сообщения, по которому имя продолжается. Указатель
   встречается как в имени записи, так и внутри данных записи — например, в `CNAME`,
   `NS` и `MX`.
5. Заголовок записи после имени занимает 10 байт: тип, класс, время жизни (32 разряда)
   и длина данных. Длину данных следует использовать для перехода к следующей записи,
   а не вычислять её по типу.
6. Ответ принимается, только если его идентификатор совпадает с идентификатором запроса;
   сообщения с другим идентификатором пропускаются, а ожидание продолжается.
7. Ответ может прийти с задержкой в несколько секунд, поэтому предел ожидания не следует
   задавать меньше указанного.

## Запуск тестов

```
make 03
```

Тестовый сервер поднимается самими тестами на локальном адресе и отдаёт заранее
заготовленные байты ответа. Обращений в интернет не требуется.

## Спецификации

- [RFC 1035](https://datatracker.ietf.org/doc/html/rfc1035) — формат сообщения, сжатие имён, коды типов и ответов
- [RFC 1034](https://datatracker.ietf.org/doc/html/rfc1034) — процедура разрешения имени, кеширование
- [RFC 3596](https://datatracker.ietf.org/doc/html/rfc3596) — запись AAAA
- [RFC 2181](https://datatracker.ietf.org/doc/html/rfc2181) — уточнения по времени жизни записи
- [RFC 5952](https://datatracker.ietf.org/doc/html/rfc5952) — текстовая запись адреса IPv6
