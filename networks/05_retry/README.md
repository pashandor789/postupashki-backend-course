# 05. Повторная отправка запроса

Программа выполняет запрос HTTP и, если ответ сервера или ошибка соединения дают на то
основания, повторяет запрос с возрастающим интервалом.

Возрастающий интервал нужен, чтобы поток повторов убывал, пока сервер не восстановится:
при фиксированном интервале отказавший сервер получает те же волны нагрузки, которые и
привели к отказу, а каждый повтор увеличивает общее число запросов без роста полезного
трафика. Случайный разброс нужен, чтобы клиенты, начавшие повторы одновременно, не
оставались синхронными: одинаковые паузы сводят все повторы в один такт и дают всплески
вместо равномерного потока. Предельное число попыток ограничивает этот рост сверху:
три повтора на каждый запрос означают четырёхкратную нагрузку на уже отказавший сервер.

## Запуск

```
run.sh <адрес ресурса> [--method <метод>] [--max-attempts <число>] [--idempotency-key <значение>]
```

| аргумент | значение | по умолчанию |
|---|---|---|
| `<адрес ресурса>` | полный адрес вида `http://127.0.0.1:8080/resource` | обязателен |
| `--method` | метод запроса | `GET` |
| `--max-attempts` | предельное число попыток, включая первую | `5` |
| `--idempotency-key` | ключ идемпотентности; передаётся в заголовке `Idempotency-Key` | не задан |

Используется только схема `http`. Предельное время ожидания ответа на одну попытку —
5 секунд; его превышение равносильно ошибке соединения.

## Вывод

Построчно, `ключ значение`, разделитель — один пробел. В отличие от остальных заданий
порядок строк значим: они печатаются в порядке событий, по мере выполнения попыток.
Лишние строки игнорируются, поэтому отладочный вывод допустим, если он не начинается
с перечисленных ключей.

| строка | когда печатается |
|---|---|
| `attempt <номер> status <код>` | попытка завершилась ответом сервера |
| `attempt <номер> error <текст>` | попытка завершилась без ответа: соединение не установлено или истекло время ожидания |
| `sleep_ms <число>` | перед каждой повторной попыткой: фактическая длительность паузы в миллисекундах |
| `result success attempts <число>` | итог работы и число выполненных попыток |
| `result failure attempts <число>` | то же при неуспешном итоге |

Попытки нумеруются с единицы. Строка `result` печатается один раз и последней.
Итог `success` соответствует коду ответа последней попытки в диапазоне от 200 до 399,
любой другой исход даёт `failure`.

Пример вывода для сервера, ответившего `503`, затем `200`:

```
attempt 1 status 503
sleep_ms 137
attempt 2 status 200
result success attempts 2
```

## Основания для повтора

| исход попытки | действие |
|---|---|
| коды `429`, `500`, `502`, `503`, `504` | повтор |
| соединение не установлено, соединение разорвано, истекло время ожидания | повтор |
| коды `400`, `401`, `403`, `404`, `422` | повтор не выполняется, итог `failure` |
| коды от 200 до 399 | повтор не выполняется, итог `success` |
| прочие коды | повтор не выполняется, итог `failure` |

Повтор выполняется, пока число выполненных попыток меньше предельного.

Метод POST не является идемпотентным: его повтор допускается только при заданном ключе
идемпотентности. Методы GET, HEAD, PUT, DELETE, OPTIONS и TRACE идемпотентны по
определению (RFC 9110, раздел 9.2.2) и повторяются без ключа.

## Расчёт интервала

Базовый интервал — 200 мс, множитель — 2, верхний предел — 2000 мс. Расчётный интервал
перед попыткой с номером n равен `min(2000, 200 × 2^(n−1))` миллисекунд. Применяется
полный случайный разброс: фактическая пауза выбирается равномерно из отрезка от нуля до
расчётного интервала и печатается в строке `sleep_ms`.

| номер попытки | расчётный интервал, мс | фактическая пауза, мс |
|---|---|---|
| 2 | 400 | от 0 до 400 |
| 3 | 800 | от 0 до 800 |
| 4 | 1600 | от 0 до 1600 |
| 5 и далее | 2000 | от 0 до 2000 |

Если ответ содержит поле `Retry-After` с числом секунд, пауза равна этому значению,
разброс не применяется и верхний предел не действует. Форма поля с датой не разбирается.

## Код возврата

0 при итоге `success`, 1 при итоге `failure`.

## Что потребуется учесть

1. Предельное число попыток включает первую: при `--max-attempts 1` повторы не выполняются.
2. Строка `sleep_ms` печатается только перед повтором; после последней попытки её быть не должно.
   Число строк `sleep_ms` на единицу меньше числа выполненных попыток.
3. Тесты измеряют паузы на стороне сервера, поэтому напечатанное значение `sleep_ms`
   должно совпадать с фактической задержкой перед следующим запросом.
4. Значение поля `Retry-After` перекрывает и расчётный интервал, и разброс.
5. POST без ключа идемпотентности не повторяется даже при коде 503: выполняется одна попытка.
6. Отсутствие слушателя на порту — основание для повтора, а не повод завершить программу
   с необработанной ошибкой.
7. Соединение открывается заново на каждой попытке; ответ следует прочитать полностью,
   иначе сервер может счесть соединение оборванным.

## Запуск тестов

```
make 05
```

Тесты поднимают сервер HTTP на localhost и выдерживают настоящие паузы, поэтому проверка
занимает около полуминуты.
